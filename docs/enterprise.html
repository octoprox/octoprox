Who got in, as well as what changed

Every edition records each change a person makes, with who made it, when and the fields it changed. Enterprise adds four things.

  1. 1

    Sign-ins

    Every sign-in by password, invite link or sign-in provider, failed ones included, with its method, the address it came from and the browser. A failed sign-in records why it was refused.

  2. 2

    API tokens

    Each personal access token issued, used for the first time and revoked, and each sign-in provider account unlinked from a user.

  3. 3

    The Activity page

    Every entry of the install on one page under Administration → Activity, the changes recorded before the license included, filtered by entity type, action, the user who acted, project and time.

  4. 4

    Export for a SIEM

    Every entry under the page's filters as JSON lines, and an audit line per entry in the server log for a log pipeline to collect.

Deployment

Same Octoprox, one image swap

Octoprox Enterprise is the public release with the Enterprise package added, published as its own image. Everything else works as it does on the free edition.

docker-compose.ghcr.yml 1 line changed 
 services:   octoprox:-    image: ghcr.io/octoprox/octoprox:latest+    image: ghcr.io/octoprox/octoprox-enterprise:{{ ent_release.version }}

  1. Run the Enterprise image

    In place of the public one. Each Enterprise release follows the public release of the same version.

  2. Keep your settings and database

    The same settings and roles, on the same database.

  3. Paste the license key

    On the License card under Administration → System, to turn on what Enterprise adds.

How licensing works

Licensing, plainly

One key turns on what Enterprise adds. Renewing, or adding seats, is a new key pasted over the old one.

Seats
Seats count active users. More active users than seats blocks nobody: admins see a banner.
A license key
oxl1.

It names

  • Organisation
  • Seats
  • Expiry date
  • Features

The License card under Administration → System shows them, with the seats in use.

Expiry, grace and after

Active up to and including the expiry date, then 30 days' grace. In every state, the license decides only what the audit log records and whether the Activity page can be read.

What is recorded and readable in each state of a license
Active Until expiry Grace period 30 days After grace Until a new key
Sign-in, passwords and tokens Work the same in every state: nobody is ever locked out
Changes, with who, when and the fields Recorded, as on every edition
Sign-ins, token events and audit lines in the server log Recorded Not recorded
The Activity page and its export Readable, so an install can still answer an auditor
Planned

Access from your directory

Later releases are planned to hand access control to your directory. None of these is available yet; Single Sign-On describes each as designed.

  • Planned Domain rules: everyone whose verified email is at your domain signs in and gets a user on first login, with a default role.

  • Planned Your own identity provider: any OpenID Connect or SAML 2.0 provider, such as Okta, Entra ID, Auth0, Keycloak or Ping.

  • Planned Group sync: roles from directory groups, re-evaluated on every sign-in.

  • Planned Enforcement: the identity provider required for everyone except break-glass admins.

  • Planned Provisioning: SCIM 2.0, so a leaver loses access the moment the directory says so.

Available today On every edition: sign-in with a password or a Google, Microsoft (one Entra tenant) or GitHub account, and personal access tokens.

01 Route

One endpoint in front of every pool

Clients send every request to one address. Octoprox picks a connector by weight, then a proxy inside it with one of five strategies.

Per request
A country, state, city or sticky session, named in the proxy username. Octoprox never silently falls back to another country.
Health checks
Once a minute by default. Failing proxies leave rotation and come back on their own once they pass again.
Per connector
Reserved and excluded countries, domain allow or block lists, and per-proxy rate limits.

Learn more about routing

02 Verify

Check where the exits really are

An exit's location comes from IP databases you host (MaxMind, DB-IP, IPinfo or IP2Location) before the vendor's claim. Each claim is confirmed, contradicted or left open, at country, state and city.

Your policy
Per project: route on the evidence, trust the vendor, or refuse.
Preflight
Optionally checks a session's exit before its first request.
Per provider
Accuracy, unique exits and IP sharing between connectors.

Learn more about IP attribution

03 Meter

See what every pool costs, and choose what happens at a cap

Bytes are metered while transfers run, per connector, per day, week or month. A price per GB shows usage as spend.

At the cap
Alert and keep routing (the default), block new requests, or also interrupt running transfers.
Your clients
When every connector that could serve a request is blocked, the client gets 509, or 429 if you set it, with an RFC 9209 Proxy-Status header.
Traffic split
Each connector's expected and observed share of requests.

Learn more about traffic limits

04 Diagnose

Know what failed, and where the time went

Requests, success rate, latency and bytes per proxy, project, connector, tunnel device and destination host, under one time range from 1h to 90d.

Failures
By kind, vendor status and connector, with the vendor's own answer.
Latency
Split into routing, preflight, connect, handshake and response: Octoprox's time apart from the vendor's.
Prometheus
Metrics per project and per process. Every API request carries an X-Request-ID that each of its log lines names.

Learn more about metrics

Works with

Every kind of pool behind one endpoint

You bring the cloud and vendor accounts. Octoprox provisions the instances, checks the proxies and meters every pool.

Cloud instances

Provisioned on demand, scaled on request rate and rotated. Run on that cloud, Octoprox can use the host's identity and store no key.

AWS Google Cloud Azure

Provider sessions

A fixed pool, or dynamic: a vendor session per request.

Bright Data Oxylabs Decodo Beta Webshare Beta IPRoyal Beta NetNut Beta

Static lists

Your own proxies over http, https, socks4 or socks5, health-checked and routed like the rest.

Static list

Custom providers

Any other vendor, added as a YAML descriptor from the admin UI, with no code or redeploy. A vendor that needs code can come as a Python plugin.

And for devices

No proxy settings? Join through a tunnel

Phones, TVs, consoles and routers join a project through a WireGuard or OpenVPN tunnel, and their connections go out through the pool.

WireGuard 51820/udp OpenVPN 1194, UDP or TCP

Quick start

Running in two commands

One process from the pre-built image, with Postgres and Redis beside it, for development, demos and small production installs.

Single instance 
# Run a single instance with the pre-built image$curl -O https://raw.githubusercontent.com/octoprox/octoprox/main/docker-compose.ghcr.yml$docker compose -f docker-compose.ghcr.yml up -d --remove-orphans

Web UI on localhost:8000, proxy on localhost:8080. Default login admin / admin.

Migrating

Coming from Scrapoxy?

The migration guide maps every Scrapoxy setting to Octoprox, and a typical setup takes well under an hour. Any vendor Octoprox does not ship can be added as a YAML descriptor, with no code or redeploy. Scrapoxy itself was discontinued in February 2026 after eleven years: images removed, docs offline, the shared GeoIP and health-check backend switched off.
